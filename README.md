## 4. Теоретические сведения

**FIRST и FOLLOW.** Для цепочки α множество FIRST(α) — терминалы, с которых начинаются цепочки, выводимые из α (и ε, если α ⇒* ε). FOLLOW(A) — терминалы, которые могут стоять сразу после A в сентенциальных формах; маркер конца ввода `$` входит в FOLLOW аксиомы.

**LL(1)-грамматика.** Грамматика принадлежит классу LL(1) тогда и только тогда, когда для любых двух правил A → α и A → β с одной левой частью множества SELECT не пересекаются, где SELECT(A → α) = FIRST(α) ∪ FOLLOW(A) при α ⇒* ε и FIRST(α) в остальных случаях. Эквивалентно: (1) FIRST(α) ∩ FIRST(β) = ∅; (2) если α ⇒* ε, то FIRST(β) ∩ FOLLOW(A) = ∅. Следствия: LL(1)-грамматика однозначна и не имеет левой рекурсии. Анализатор нисходящий: читает вход слева направо, строит левый вывод, выбор правила определяется нетерминалом на вершине стека и одним символом предпросмотра.

**Метод рекурсивного спуска.** Каждому нетерминалу ставится в соответствие процедура, тело которой реализует выбор правила по символу предпросмотра: терминал сопоставляется с входом, нетерминал — вызов процедуры. Для LL(1)-грамматики такой анализатор детерминирован и не требует возвратов.

**SLR(1)-анализ.** Восходящий анализ: перенос-свёртка по таблице. LR(0)-ситуация — правило с точкой в правой части (`A → α·β`). Каноническая система строится из замыкания CLOSURE и переходов GOTO, начиная с ситуации `S' → ·S` пополненной грамматики. Таблица SLR(1): перенос `s j` по терминалу `a`, если `A → α·aβ ∈ I` и `GOTO(I, a) = j`; свёртка `r k` по правилу `A → α` на всех терминалах из FOLLOW(A), если `A → α· ∈ I`; допуск — в состоянии с `S' → S·` на `$`; переходы по нетерминалам — GOTO. Грамматика SLR(1), если в таблице нет клеток с несколькими действиями (конфликтов перенос/свёртка и свёртка/свёртка).

## 5. Часть 1. LL(1)-грамматика (JFLAP)

### 5.1. Обозначения нетерминалов

| Нетерминал | Назначение |
|---|---|
| `S` | оператор присваивания |
| `V` | имя переменной (`a`–`d`) |
| `E`, `A` | аддитивный уровень: терм и «хвост» из `+T` / `-T` |
| `T`, `M` | мультипликативный уровень: множитель и «хвост» из `*U` / `:U` |
| `U` | унарные операции |
| `P` | первичное выражение: дробь, переменная или выражение в скобках |
| `F` | не смешанная дробь `N/N` |
| `N`, `L` | непустая последовательность цифр: первая цифра и остаток |
| `D` | десятичная цифра |

### 5.2. Грамматика (`CFG_LL1.jff`)

```
S → V=E
V → a | b | c | d
E → TA
A → +TA | -TA | ε
T → UM
M → *UM | :UM | ε
U → +U | -U | P
P → F | V | [E]
F → N/N
N → DL
L → DL | ε
D → 0|1|…|9
```

**Обоснование.** Левая рекурсия, свойственная левоассоциативным операциям (`E → E+T`), заменена правой: `E → TA`, `A → +TA | -TA | ε` — аналогично для мультипликативного уровня (`T → UM`, `M → *UM | :UM | ε`) и для последовательности цифр (`N → DL`, `L → DL | ε`). Унарные операции правоассоциативны и записаны правой рекурсией `U → +U | -U | P`. Левое общее начало у правил `P` отсутствует: дробь начинается с цифры, переменная — с `a`–`d`, скобка — с `[`. Приоритеты обеспечены уровнями вложенности (от низшего к высшему): `S` (присваивание) → `E` (аддитивные) → `T` (мультипликативные) → `U` (унарные) → `P`. Ассоциативность бинарных операций в этой грамматике правая (следствие правой рекурсии, выбор разработчика); множество принимаемых цепочек от неё не зависит.

### 5.5. Пример разбора

Цепочка `a=1/2+b`. Левый вывод, построенный анализатором по таблице:

```
S ⇒ V=E ⇒ a=E ⇒ a=TA ⇒ a=UMA
⇒ a=PMA ⇒ a=FMA ⇒ a=N/NMA ⇒ a=DL/NMA ⇒ a=1L/NMA
⇒ a=1/NMA ⇒ a=1/DLMA ⇒ a=1/2LMA ⇒ a=1/2MA ⇒ a=1/2A
⇒ a=1/2+TA ⇒ a=1/2+UMA ⇒ a=1/2+PMA ⇒ a=1/2+VMA ⇒ a=1/2+bMA
⇒ a=1/2+bA ⇒ a=1/2+b
```

## 6. Часть 2. Метод рекурсивного спуска (`rd_parser.py`)

### 6.1. Язык и лексемы

Язык — непустая последовательность выражений, разделённых `;`. Лексический анализ выполняется до синтаксического; пробелы, табуляции и переводы строк пропускаются.

| Лексема | Определение | Терминал грамматики |
|---|---|---|
| число | `[0-9]+` (целое) или `[0-9]+/[0-9]+` (рациональная дробь) | `n` |
| имя | одна или две латинские буквы | `i` |
| знаки | `+` `-` `*` `:` `=` `(` `)` `;` | сами символы |

Всё остальное — лексическая ошибка: символ вне алфавита; дробь без знаменателя (`1/`); имя длиннее двух букв (`abc`); `/` вне дроби (например `1/2/3` или `1 / 2`).

### 6.2. Грамматика

Исходная («естественная») грамматика языка неоднозначна и леворекурсивна (`Arith → Arith + Arith`), а у `Expr → Id = Expr | Arith` два правила могут начинаться с имени, поэтому LL(1) она не является. Преобразования: устранение левой рекурсии (`R`, `A`), левая факторизация общего начала `Id` (нетерминал `T` — «что следует за именем: `=` или продолжение арифметического выражения»), разделение уровней приоритетов. Левый операнд присваивания остаётся строго именем: после `i` допускается `=`, а после числа, скобок или унарного знака — нет.

```
S → EQ
Q → ;K | ε
K → EQ | ε
E → iT | nRA | (E)RA | +URA | -URA
T → =E | RA
U → +U | -U | n | i | (E)
R → *UR | :UR | ε
A → +MA | -MA | ε
M → UR
```

| Нетерминал | Процедура | Назначение |
|---|---|---|
| `S` | `program` | вся последовательность |
| `Q` | `program (цикл)` | остаток после первого выражения |
| `K` | `program (цикл)` | выражение после `;` либо конец |
| `E` | `expr` | выражение с присваиванием |
| `T` | `tail` | продолжение после имени |
| `U` | `unary` | унарные знаки и операнд |
| `R` | `mul_rest` | хвост мультипликативных операций |
| `A` | `add_rest` | хвост аддитивных операций |
| `M` | `mul` | множитель аддитивного уровня |

### 6.3. Множества FIRST и FOLLOW

(Терминалы: `i` — имя, `n` — число.)

| Нетерминал | FIRST | FOLLOW |
|---|---|---|
| `S` | `+`, `-`, `(`, `i`, `n` | `$` |
| `Q` | `;` (и ε) | `$` |
| `K` | `+`, `-`, `(`, `i`, `n` (и ε) | `$` |
| `E` | `+`, `-`, `(`, `i`, `n` | `;`, `)`, `$` |
| `T` | `+`, `-`, `*`, `:`, `=` (и ε) | `;`, `)`, `$` |
| `U` | `+`, `-`, `(`, `i`, `n` | `+`, `-`, `*`, `:`, `;`, `)`, `$` |
| `R` | `*`, `:` (и ε) | `+`, `-`, `;`, `)`, `$` |
| `A` | `+`, `-` (и ε) | `;`, `)`, `$` |
| `M` | `+`, `-`, `(`, `i`, `n` | `+`, `-`, `;`, `)`, `$` |

### 6.4. Формальное доказательство принадлежности к классу LL(1)

**Утверждение.** Грамматика части 2 принадлежит классу LL(1).

**Доказательство.** По критерию из раздела 4 достаточно проверить, что для каждого нетерминала с несколькими правилами множества SELECT этих правил попарно не пересекаются. Нетерминалы с единственным правилом (`M → UR`, `S → EQ`) условия не требуют. Множества SELECT вычислены из FIRST и FOLLOW (раздел 6.3):

| Правило | SELECT = FIRST(α) ∪ (FOLLOW(A), если α ⇒* ε) | Пересечение с другими правилами того же нетерминала |
|---|---|---|
| `S → EQ` | `i`, `n`, `+`, `-`, `(` | — (одно правило) |
| `Q → ;K` | `;` | ∅ |
| `Q → ε` | `$` | ∅ |
| `K → EQ` | `i`, `n`, `+`, `-`, `(` | ∅ |
| `K → ε` | `$` | ∅ |
| `E → iT` | `i` | ∅ |
| `E → nRA` | `n` | ∅ |
| `E → (E)RA` | `(` | ∅ |
| `E → +URA` | `+` | ∅ |
| `E → -URA` | `-` | ∅ |
| `T → =E` | `=` | ∅ |
| `T → RA` | `+`, `-`, `*`, `:`, `)`, `;`, `$` | ∅ |
| `U → +U` | `+` | ∅ |
| `U → -U` | `-` | ∅ |
| `U → n` | `n` | ∅ |
| `U → i` | `i` | ∅ |
| `U → (E)` | `(` | ∅ |
| `R → *UR` | `*` | ∅ |
| `R → :UR` | `:` | ∅ |
| `R → ε` | `+`, `-`, `)`, `;`, `$` | ∅ |
| `A → +MA` | `+` | ∅ |
| `A → -MA` | `-` | ∅ |
| `A → ε` | `)`, `;`, `$` | ∅ |
| `M → UR` | `i`, `n`, `+`, `-`, `(` | — (одно правило) |

Разбор по нетерминалам:

* `Q`: `;` ∈ SELECT(`Q → ;K`), `$` ∈ SELECT(`Q → ε`) (так как `$` ∈ FOLLOW(`Q`) = FOLLOW(`S`)); `;` ≠ `$`.
* `K`: FIRST(`EQ`) = {`i`, `n`, `(`, `+`, `-`}, а FOLLOW(`K`) = {`$`}; пересечения нет.
* `E`: правила начинаются с пяти различных терминалов `i`, `n`, `(`, `+`, `-`; ни одно правило не выводит ε.
* `T`: SELECT(`T → =E`) = {`=`}; SELECT(`T → RA`) = {`*`, `:`, `+`, `-`} ∪ FOLLOW(`T`) = {`*`, `:`, `+`, `-`, `;`, `)`, `$`}. Символ `=` не входит в FOLLOW(`E`) = {`;`, `)`, `$`} = FOLLOW(`T`) — именно поэтому присваивание нельзя применить к результату бинарной операции. Пересечение пусто.
* `U`: пять правил начинаются с пяти различных терминалов `+`, `-`, `n`, `i`, `(`.
* `R`: `*`, `:` против FOLLOW(`R`) = {`+`, `-`, `;`, `)`, `$`}; пересечения нет (за `R` следует либо `A`, начинающийся с `+` или `-`, либо то, что следует за `M`, `T` или `E`).
* `A`: `+`, `-` против FOLLOW(`A`) = {`;`, `)`, `$`}; пересечения нет.

Левой рекурсии нет: рассмотрим отношение «нетерминал `B` может стоять первым в выводе из `A`» (с учётом ε-выводимых префиксов): `S → E`, `K → E`, `M → U`, `T → R`, `T → A`; остальные нетерминалы (`E`, `U`, `R`, `A`, `Q`) начинаются с терминала. Граф отношения ацикличен, поэтому ни один нетерминал не выводит цепочку, начинающуюся с него самого. Следовательно, условия критерия выполнены для всех нетерминалов, грамматика LL(1). ∎

### 6.5. Реализация

* **Лексер** `tokenize()` — конечный автомат по символам; возвращает лексемы `NUM`, `ID`, знаки, `EOF` и лексемы-ошибки `BAD` с текстом диагностики.
* **Парсер** — класс `Parser`; по одной процедуре на нетерминал (`program`, `expr`, `tail`, `unary`, `mul`, `mul_rest`, `add_rest`), выбор правила по текущей лексеме (`cur.kind`). ε-правила `R → ε`, `A → ε` выбираются, когда лексема входит в FOLLOW (`FOLLOW_R`, `FOLLOW_A` в коде) — на любой другой лексеме вызывается `fail()`. Хвостовые рекурсии `R → *UR`, `A → +MA`, `Q → ;K` реализованы циклами (`while`), что эквивалентно рекурсивному спуску по правилам.
* **Диагностика и восстановление (бонус).** При ошибке формируется сообщение «строка, столбец, что ожидалось и что найдено» (лексические ошибки — с описанием причины); затем анализатор пропускает вход до ближайшего `;` и продолжает со следующего выражения, поэтому за один запуск сообщается обо всех ошибочных выражениях. В stdout всегда выводится одно слово `Accepted` или `Rejected`, диагностика идёт в stderr.

Запуск:

```
python rd_parser.py "x = 1/2 + y; z = -(x : 3)"
```

## 7. Часть 3. SLR(1)-грамматика (JFLAP)

### 7.1. Грамматика (`CFG_SLR1.jff`)

```
S → R | R;
R → R;A | A
A → V=E
E → E+T | E-T | T
T → T*Y | T:Y | Y
Y → +Y | -Y | P
P → [E] | V | F
F → N/N
N → ND | D
D → 0|1|…|9
V → a | b | c | d
```

Нумерация правил (используется в таблице):

| № | Правило |
|---|---|
| 1 | `S → R` |
| 2 | `S → R;` |
| 3 | `R → R;A` |
| 4 | `R → A` |
| 5 | `A → V=E` |
| 6 | `E → E+T` |
| 7 | `E → E-T` |
| 8 | `E → T` |
| 9 | `T → T*Y` |
| 10 | `T → T:Y` |
| 11 | `T → Y` |
| 12 | `Y → +Y` |
| 13 | `Y → -Y` |
| 14 | `Y → P` |
| 15 | `P → [E]` |
| 16 | `P → V` |
| 17 | `P → F` |
| 18 | `F → N/N` |
| 19 | `N → ND` |
| 20 | `N → D` |
| 21–30 | D → 0 \| 1 \| … \| 9 |
| 31–34 | V → a \| b \| c \| d |

**Отличие от LL(1)-грамматики части 1.** Грамматика части 3 леворекурсивна по всем бинарным уровням (`E → E+T | E-T`, `T → T*Y | T:Y`), по последовательности операторов (`R → R;A`) и по цифрам (`N → ND`); в ней нет нетерминалов `M`, `L`, `U` и ε-правил, у присваивания отдельный нетерминал `A`, а первичное выражение и унарный уровень переименованы (`Y`, `P`). Ассоциативность бинарных операций левая. Левая рекурсия недопустима в LL(1)-грамматике (раздел 4), поэтому грамматика части 3 не совпадает с LL(1)-грамматикой части 1 и не может быть LL(1) без преобразования. Однозначность и приоритеты обеспечены теми же уровнями, что и в части 1: `E` (аддитивные) → `T` (мультипликативные) → `Y` (унарные) → `P` (от низшего приоритета к высшему). Нетерминал `S` не встречается в правых частях.

### 7.4. Таблица синтаксического анализа SLR(1)

Запись `s j` — перенос и переход в состояние `j`; `r k` — свёртка по правилу № `k`; `acc` — допуск; пустая клетка — ошибка. Столбцы `0–9` и `a–d` объединяют 10 и 4 одинаковых столбца: `s d_c` — перенос в состояние `d_c` для прочитанной цифры `c`, `s v_x` — для прочитанной буквы `x`. Строки `d_c` и `v_x` — свёртки `D → c`, `V → x` (соответственно правила 21–30 и 31–34).

Конфликтов нет: в каждой клетке не более одного действия. Контрольные места:

* состояния 9, 28, 29 (`E → T·`, `E → E+T·`, `E → E-T·` и `T → T·*Y`, `T → T·:Y`): свёртка выполняется по FOLLOW(`E`) = {`+`, `-`, `)`, `;`, `$`}, перенос — по `*` и `:`; множества не пересекаются;
* состояние 2 (`S → R·`, `S → R·;`, `R → R·;A`): свёртка по `$`, перенос по `;`;
* состояния 13 и 32 (`F → N·/N` / `F → N/N·` и `N → N·D`): перенос по цифрам и `/`, а свёртка `F → N/N` — только по FOLLOW(`F`), в котором нет цифр;
* состояние 4 (`A → V·=E`): единственное действие — перенос `=`; в состоянии 15 (`P → V·`) свёртка по FOLLOW(`P`), где нет `=`; именно поэтому имя слева от `=` и имя в выражении не конфликтуют (они возникают в разных состояниях).

## 8. Заключение

В ходе работы исследованы контекстно-свободные грамматики и алгоритмы нисходящего и восходящего синтаксического анализа. Для языка оператора присваивания с не смешанными дробями (переменные `a`–`d`, унарные и бинарные операции) построена LL(1)-грамматика: левая рекурсия заменена правой, вычислены FIRST/FOLLOW, таблица разбора не содержит конфликтов. Для языка последовательностей выражений с дробями, целыми константами и именами из 1–2 символов реализован синтаксический анализатор методом рекурсивного спуска; принадлежность его грамматики классу LL(1) доказана через попарную непересекаемость множеств SELECT, анализатор выводит «Accepted»/«Rejected» и информативные сообщения об ошибках с восстановлением. Для языка последовательностей операторов присваивания построена леворекурсивная SLR(1)-грамматика, отличная от LL(1)-грамматики части 1; построены канонический набор LR(0)-ситуаций (48 состояний) и таблица SLR(1) без конфликтов.
